## 2. URL structure

Every user-facing route is language-prefixed. This is the single most consequential SEO decision in the project and it is the right one for a trilingual regional directory.

```
/                           → 301-style client redirect to /uz
/:lang                      home
/:lang/search               search + map          (?category=, ?q=, ?district=, ?city=)
/:lang/business/:slug       business detail       ← the canonical money page
/:lang/events               events
/:lang/pricing              pricing
/:lang/signup               signup
/:lang/claim                claim
/:lang/favorites            private
/:lang/profile              private
/:lang/dashboard            private
/:lang/admin                private
```

**Strengths**
- One entity, three addressable URLs (`/uz/business/x`, `/ru/business/x`, `/en/business/x`), each declaring the others via `hreflang`. This is exactly what Google wants.
- `Business.slug` is globally `@unique` and `VarChar(180)` — the schema comments it as *"canonical: /business/:slug"*.
- Slugs are generated by a `slugify()` that strips Uzbek apostrophe variants (`'`, `’`, `ʻ`, `ʼ`, `` ` ``), so `O'zbekiston` → `ozbekiston` rather than producing a broken slug.

**Weaknesses**
- **`/` redirects to `/uz` client-side**, not with a server 301. Crawlers must execute JS to follow it.
- **Superseded 2026-10-01 (Phase 7).** Real `/category/:slug` and `/district/:slug` routes now exist with unique H1/meta/copy — see §11. The one exception: the `oziq-ovqat` (food) category's homepage tile still links to `/search?category=oziq-ovqat`, deliberately, because that query preserves the specialized restaurant search UI (`CategorySearchPage`, a locked decision — `DECISIONS.md` D-21). `/category/oziq-ovqat` still exists and is still the sitemapped, canonical page for that category; only the one homepage internal link was kept pointing at the enhanced UX variant instead.
- **No trailing-slash policy** stated anywhere.

## 3. Metadata

`src/components/seo/MetaTags.tsx` — one component, used by **13 pages**.

```tsx
<MetaTags title description image? type? noIndex? />
```

Callers pass only what is page-specific. Everything language-derived — canonical, alternates, `og:locale` — is computed from the router, so **every page gets it without opting in**.

Emitted tags:

| Tag | Source |
| --- | --- |
| `<html lang>` | current language |
| `<title>` | caller |
| `<meta name="description">` | caller |
| `<link rel="canonical">` | `SITE_URL + pathForLang(pathname, lang)` |
| `<meta name="robots" content="noindex, nofollow">` | when `noIndex` — and then **no** canonical and **no** hreflang alternates (Phase 16F.1: canonical + noindex are contradictory signals) |
| `<link rel="alternate" hreflang>` ×3 | `uz`, `ru`, `en` |
| `<link rel="alternate" hreflang="x-default">` | points at the **`uz`** URL |
| `og:site_name`, `og:title`, `og:description`, `og:type`, `og:url`, `og:image` (+ `width` 1200, `height` 630), `og:locale` | |
| `og:locale:alternate` ×2 | the other two languages (`uz_UZ`, `ru_RU`, `en_US`) |
| `twitter:card` (`summary_large_image`), `twitter:title`, `twitter:description`, `twitter:image` | |

**Coverage:** `HomePage`, `SearchPage`, `CategorySearchPage`, `BusinessDetailPage`, `EventsPage`, `PricingPage`, `SignupPage`, `ClaimPage`, `FavoritesPage`, `ProfilePage`, `OwnerDashboard`, `AdminDashboard`, `AddBusinessPage` — i.e. **all public pages plus the private ones (which pass `noIndex`)**.

**Not-found states (Phase 16F.1).** Because the SPA answers `200` for every URL, a missing page is kept out of the index with `noindex`, not a status code. `NotFoundState` renders the empty state plus `MetaTags noIndex` (title `"<not found> — My Andijan"`) when the absence is **confirmed** — business/category/event `404`, or a district slug matching nothing in the loaded list. A transient failure (network/5xx) emits no head tags, so a crawler that hits a blip is not told to drop a real page. Unknown paths under `/:lang` reach the `*` route (`NotFoundPage`, always noindex), and a first segment that is not `uz`/`ru`/`en` is redirected under `/uz` (`LangShell`) instead of rendering the homepage.

**Supporting module `src/lib/seo.ts`:**
- `SITE_URL` from `VITE_SITE_URL`, defaulting to `https://myandijan.uz`, trailing slash stripped. **Deploy previews should set `VITE_SITE_URL`** so they don't advertise production as their canonical — this is documented in the file and is a genuinely thoughtful detail.
- `OG_LOCALE` maps bare language codes to full locales.
- `absoluteUrl()` resolves relative paths, passing absolutes through.
- `pathForLang()` swaps the leading language segment.

**Known implementation note:** no React fragments may appear inside `<Helmet>` — `react-helmet-async` accepts only plain elements and arrays. The component is written accordingly; preserve that.

### Title/description generation
**Titles and descriptions are composed by each calling page**, not by a central generator. There is **no shared template** (e.g. `"{name} — {category} in {district} | My Andijan"`), and no fallback if a page passes an empty string. For a directory that will eventually have thousands of business pages, a single templating helper is worth adding.

The database supports per-entity overrides — `Business.metaTitleUz/Ru/En` and `metaDescriptionUz/Ru/En`, documented as *"SEO overrides (fall back to generated values when null)"*. **No admin or owner UI writes these columns, and no frontend code reads them.** The capability exists and is unused end to end.

## 4. Structured data (schema.org)

`src/components/seo/JsonLd.tsx` — a discriminated union so passing the wrong data shape for a type is a **compile error**, not silently invalid markup.

### Types supported

**`LocalBusiness`** — `name` (required), plus conditionally `description`, `image`, `url`, `telephone`, `address` (`PostalAddress` with `addressRegion` defaulting to `"Andijon Region"` and `addressCountry: "UZ"`), `geo` (`GeoCoordinates`), `openingHoursSpecification`, `aggregateRating`, `sameAs`.

**`WebSite`** — with a `SearchAction` `potentialAction` whose `urlTemplate` is `{searchPath}?q={search_term_string}`, enabling a Google sitelinks search box.

**`BreadcrumbList`** — positional `ListItem`s with absolute URLs.

### Three details that are done right

1. **`aggregateRating` is omitted entirely when `reviewCount` is 0.** The code comments why: *"Google rejects — and flags as an error — an AggregateRating with no reviews behind it."* With 4 businesses and almost no reviews live, this is currently load-bearing.
2. **Opening hours are filtered before emission** — only days that are not closed and have both `openTime` and `closeTime` produce an `OpeningHoursSpecification`. The `SCHEMA_DAYS` array is **Monday-first**, matching the app's `0 = Monday` convention. Getting this wrong would silently publish incorrect hours.
3. **`</script>` injection is defended against**: `JSON.stringify(schema).replace(/</g, "\\u003c")` — so a stray `</script>` inside API-sourced business text cannot close the tag early.

### Coverage and gaps

| Page | JSON-LD |
| --- | --- |
| `HomePage` | ✅ `WebSite` (+ `SearchAction`) |
| `BusinessDetailPage` | ✅ `LocalBusiness` |
| Everything else | ❌ none |

**Missing types that would matter:**
- **`BreadcrumbList` is built but never used.** The builder exists; no page emits it.
- **No `Review` / `Product` / `Menu` markup** on business pages, despite reviews and menus being modelled and displayed.
- **No `Event` markup** on the events page, despite a complete `Event` model with `startAt`, `endAt`, `venueName`, `price`, `isFree` — everything `schema.org/Event` needs.
- **No `Organization`** for My Andijan itself.
- `LocalBusiness` is used generically rather than a specific subtype (`Restaurant`, `Store`, `BeautySalon`…), even though `Category` and `BusinessType` carry enough information to choose one. Specific subtypes unlock richer results.

## 5. `robots.txt`

```
User-agent: *
Allow: /

Disallow: /admin
Disallow: /dashboard
Disallow: /owner
Disallow: /*/admin
Disallow: /*/dashboard
Disallow: /*/owner
Disallow: /*/profile
Disallow: /*/favorites

Sitemap: https://myandijan.uz/sitemap.xml
```

**Correct, and for a non-obvious reason the file itself documents:** every route is language-prefixed, so `Disallow: /admin` alone would not cover `/uz/admin` — hence the `/*/` wildcard duplicates. This is the kind of mistake that is normally shipped and never noticed.

Two notes:
- `/owner` is disallowed but **is not a route** — harmless.
- `/signup` and `/claim` are **allowed**, which is correct: the claim page is a business-acquisition landing page and should rank.

## 6. Sitemaps

`public/sitemap.xml` is a `sitemapindex` pointing at four files.

> **Superseded 2026-10-01 (Phase 7).** Regenerated after building real `/category/:slug` and `/district/:slug` routes (see §11). Every URL below now resolves to a real, indexable page — none are query-string search pages.

| File | URLs | State |
| --- | --- | --- |
| `sitemap-pages.xml` | 9 | ✅ |
| `sitemap-categories.xml` | 24 (8 categories × 3 languages) | ✅ each now resolves to a dedicated `/category/:slug` page |
| `sitemap-locations.xml` | 42 (14 districts × 3 languages) | ✅ each now resolves to a dedicated `/district/:slug` page. **City URLs removed** — no `/:lang/city/:slug` route exists, and a URL with no matching route would point crawlers at the SPA's empty-`Layout` fallback rather than content (see §9's canonical-safety note) |
| `sitemap-businesses.xml` | 12 (4 businesses × 3 languages) | ✅ populated in Phase 5 |

### Generator: `scripts/generate-sitemap.ts` (`npm run sitemap`)

The script is well-built:
- Fetches **live API data** for regions/districts/cities, categories and businesses.
- Emits **every URL once per language with a full set of `xhtml:link` alternates** — the file states this is *"what Google wants for a directory that serves the same entity at /uz/, /ru/ and /en/."*
- **Deliberately omits `<priority>` and `<changefreq>`** because Google ignores both. Correct.
- Pages the business list at `PAGE_SIZE = 100` (*"The API rejects limit > 100 with a 400"*), capped at `MAX_PAGES = 200`.
- Narrow API interfaces on purpose, so an unrelated payload change cannot break it.
- Configurable via `SITE_URL` and `VITE_API_URL`.
- 30 s request timeout.

**Phase 16F.4 — all-or-nothing, and the full category tree.** The original generator turned any failed request into an empty list and wrote the files anyway, so running it while the API was down silently replaced the committed business/category/location sitemaps with empty ones and still exited 0. It now fetches everything first: a failed, non-2xx, malformed or truncated (> `MAX_PAGES`) response aborts **before any file is written**, prints `Sitemap generation aborted — no files were written`, and exits 1. Categories now come from `GET /categories` (every active category, nested ones included) instead of `GET /categories/homepage`, which only held the homepage tiles. Split into `scripts/sitemap/build.ts` (pure XML building) and `scripts/sitemap/generate.ts` (fetch + write, network/disk injected), both covered by `scripts/sitemap/__tests__`. **Regenerating the committed files needs the live API** (Railway) — the XML in `public/` is unchanged by this phase.

**Phase 16F.5 — event detail pages.** A fifth sub-sitemap, `sitemap-events.xml`, lists every `/:lang/events/:slug` page from the paginated public `GET /events` (only PUBLISHED, non-deleted events — exactly what `GET /events/:slug` serves; past events included, since their pages still resolve). No `lastmod`: the list returns no `updatedAt`, and `startAt` is not a modification date. Fetched with the same all-or-nothing rules. The index lists the new file once the generator next runs against the live API; until then `public/` is unchanged.

### Why the business sitemap is empty — and the fix

**The generator is not broken. It was last run when the API genuinely had zero businesses** (`docs/SSG.md` records that state: *"the API returns zero businesses"*). The live API now returns **4**.

```bash
npm run sitemap
```

That single command should populate `sitemap-businesses.xml` and refresh every `lastmod`. **This is the cheapest SEO win available in the project.** It must also be re-run on a schedule or as part of the build, because the committed sitemap is a static artifact that goes stale the moment a business is added — and nothing currently re-runs it.

## 7. Canonical URLs

Handled entirely in `MetaTags`: `canonical = SITE_URL + pathForLang(pathname, lang)`.

**Correct behaviours**
- Each language variant self-canonicalises (does **not** point at `uz`), with `hreflang` expressing the relationship. This is the right pattern — a wrong implementation here would de-index two thirds of the site.
- `VITE_SITE_URL` lets previews avoid claiming the production canonical.

**Gaps**
- **Query parameters are included in the canonical**, because `pathname` is used but search params are not stripped or normalised. `/uz/search?category=oziq-ovqat&page=2` canonicalises to `/uz/search` — which is actually the desired collapse — but **`useLocation().pathname` excludes the query string entirely**, so every variant of `/uz/search` shares one canonical. That is fine for search, and it means paginated result pages cannot be individually canonicalised if that is ever wanted.
- No `rel="prev"`/`rel="next"` on paginated results.

## 8. Indexing strategy

**Declared intent:**
- Index: home, search, business detail, events, pricing, signup, claim
- Exclude: admin, dashboard, profile, favourites — via **both** `robots.txt` and `MetaTags noIndex`, which is the belt-and-braces approach

**The actual constraint is rendering, not directives.** The app is a pure SPA. `index.html` contains:

```html
<title>My Andijan — Andijon viloyatidagi bizneslar</title>
```

…and **no `<meta name="description">`, no Open Graph tags, no JSON-LD.** Everything SEO-relevant is injected by `react-helmet-async` after hydration.

Consequences, as `docs/SSG.md` states plainly:

1. **Googlebot does render JavaScript**, so it will eventually see the injected tags — but pages go through the render queue rather than being indexed on first fetch. **Slower indexing, not no indexing.**
2. **Social scrapers (Facebook, Telegram, X, WhatsApp) do not run JavaScript.** They see only `index.html`. So **every shared link — including every business page — previews with the same generic title, no description and no image.**

Point 2 is the real cost, and `docs/SSG.md` names it as *"the strongest argument for doing Phase 2 before launch rather than after."* **For a local directory in a Telegram-heavy market, link sharing is a primary acquisition channel. This deserves to be treated as a launch blocker, not a Phase-2 nicety.**

**A cheap partial mitigation** that does not require SSR: add a static `<meta name="description">` and a default OG block (`og:title`, `og:description`, `og:image`, `og:type`, `og:url`) to `index.html`. Shared links would then preview with correct branding and the default OG card instead of a bare title. It does not give per-business previews, but it converts a broken preview into an acceptable one for a few lines of HTML.

## 9. SSR / SSG

**Not implemented. Deliberately deferred, with a written plan** — `docs/SSG.md`, authored in "Session J".

### Why it was deferred (three real blockers, all verified)

1. **`App.tsx` hardcodes `BrowserRouter`.** Server rendering needs `StaticRouter` fed the incoming URL. As written there is no seam — `App` owns the router, so both entry points would get the browser one and `renderToString` throws.
2. **`LanguageProvider` reads `localStorage` during render** (`src/contexts/LanguageContext.tsx` — confirmed: `lang` resolves from `useParams` then `localStorage.getItem(STORAGE_KEY)` synchronously in the component body). `AuthContext` does the same for the token via `useState` initialisers. `localStorage` does not exist in Node, so the first render crashes before any markup is produced.
3. **Leaflet touches `window` at module scope.** Prerendering `/uz/search` would need the map excluded from SSR.

Blocker 2 is a behaviour change to auth and language resolution, which is why it was judged out of scope for an SEO-focused session.

### The recorded plan

- **Target routes:** `/{uz,ru,en}/`, `/{uz,ru,en}/search`, `/{uz,ru,en}/events`. Business detail pages stay on the SPA fallback until the API has real slugs (**now it does** — that caveat is resolved).
- **Step 1:** extract `AppShell.tsx` (everything inside the router, no router); `main.tsx` wraps it in `BrowserRouter`, the server entry in `StaticRouter location={url}`. `HelmetProvider` must move inside whichever entry renders, and the server needs its `context` object to read collected tags back out.
- **Step 2:** guard every `localStorage` read with `typeof window === "undefined"`.
- **Step 3:** isolate `SearchMap` behind `lazy()` + a mounted check.
- **Step 4:** prefer **`vite-plugin-prerender` or a post-build `renderToString` script** over Vike — smallest blast radius; dev server and build stay as they are, and the SPA keeps working if prerendering is switched off.
- **Step 5:** hosting must serve `dist/uz/index.html` for `/uz/` while still falling back to `index.html` for unknown paths. On Vercel that is a rewrite rule.
- **Verification:** `curl -s https://myandijan.uz/uz/ | grep -o '<title>[^<]*</title>'` — if the title comes back without JavaScript, prerendering is live.

**This plan is good and should be followed rather than re-derived.**

## 10. Internal linking

**What exists**
- Home → categories, districts, featured businesses, CTA banner (now pointing at `/claim`)
- Search results → business detail
- Business detail → `SimilarBusinesses` (a genuine same-category link cluster) and `BranchesSection`
- `Header` / `Footer` / `MobileNav` global navigation
- Language switcher produces cross-language links on every page
- Legacy redirects preserve link equity from old paths (`/register`, `/business/claim`, `/dashboard/business/:id/edit`)

**What is missing**
- **No breadcrumbs rendered anywhere**, even though the `BreadcrumbList` JSON-LD builder exists. Breadcrumbs would give both users and crawlers a Home → Category → District → Business hierarchy.
- **No category → category links** (no parent/child navigation), so the `Category` tree is invisible to crawlers.
- **No district → business links** outside of search queries.
- **No cross-linking from events to their business**, though `Event.businessId` is required.
- No tag/cuisine hub pages — the cuisine chips are client-side filter state, not linkable URLs.

## 11. Category & location pages — IMPLEMENTED 2026-10-01 (Phase 7)

Real, indexable, language-prefixed routes now exist:

- **`/:lang/category/:slug`** — `CategoryLandingPage.tsx`. Backed by `GET /categories/:slug` (pre-existing, previously unused) for the category's localized name, plus `GET /businesses?category=<slug>` (via the existing `useSearchBusinesses` hook — same hook `SearchPage` uses) for the real, paginated, status-filtered business list. Both pages reuse `BusinessListCard` and `Pagination` verbatim (no duplicate card component), the existing loading/empty/error state conventions, and `MetaTags`/`JsonLd` for SEO — canonical, hreflang ×3 + x-default, Open Graph, and a `BreadcrumbList` schema (Home → Category/District list → this page), all with **real data**: the business count in the title/description/on-page copy comes from the actual filtered `meta.total` on the businesses list, never from the category's own `_count.businesses` (which isn't status-filtered) or an invented number.

**One deliberate exception:** the `oziq-ovqat` (food) category's homepage tile still navigates to `/search?category=oziq-ovqat`, not `/category/oziq-ovqat`, to preserve the specialized restaurant search UI (`CategorySearchPage` — a locked decision, `DECISIONS.md` D-21). `/category/oziq-ovqat` still exists, still renders, and is still the one sitemapped/canonical URL for that category — only that one homepage click target was special-cased. See `ARCHITECTURE.md` §24 for the full implementation record and `DECISIONS.md` D-55 for the URL-structure decision.

## 13. What not to break

1. **Language-prefixed URLs and self-canonicalising `hreflang`.** Collapsing to a single canonical would de-index two of three languages.
2. **The conditional `aggregateRating`.** Emitting it with zero reviews produces a Search Console error.
3. **The `</script>` escape in `JsonLd`.**
4. **Monday-first `SCHEMA_DAYS`.** Off by one publishes wrong opening hours.
5. **Omitting `priority`/`changefreq`** from sitemaps — a deliberate, correct choice.
6. **The `/*/` wildcards in `robots.txt`.** Removing them exposes `/uz/admin` etc.
7. **No React fragments inside `<Helmet>`.**
8. **`VITE_SITE_URL` support** — it is what stops preview deploys from claiming the production canonical.
